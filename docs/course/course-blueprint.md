# Teaching Practice Lab Course Blueprint

This is the working blueprint for the full public learning experience.

The course is built to answer one practical question:

> Can the learner explain and defend instructional decisions using the framework without relying on a checklist or memorized script?

## Course structure

### Module 00 — Foundations: Think Like the Framework

Purpose: learn the reasoning loop before learning the 23 current competencies.

Lessons:

1. Framework Orientation
2. Desired Effect
3. Evidence vs Activity
4. Not Enough Evidence
5. Adaptation Loop
6. Distinguish the Concepts
7. Applied Scenario
8. Defend the Decision
9. Integrated Observation

Required practice types:

- evidence selection,
- non-example analysis,
- insufficient-evidence cases,
- adaptation decisions,
- mixed classroom scenarios,
- spoken defense prompts.

## Module 01 — Standards-Based Planning

Purpose: learn to reason from standards and learning targets into tasks, resources, cognitive demand, and evidence.

Research items before full authoring:

- verify the exact canonical labels of all three current planning competencies,
- gather authoritative current material on target-task alignment,
- gather current material on measures/progress monitoring within planning,
- identify how current FTEM describes planning for achievement gaps.

Likely course themes:

- standards and learning targets,
- cognitive demand,
- target-task alignment,
- resource selection,
- evidence planning,
- planning for learner variation.

High-value scenarios:

- target asks for analysis but task only requires recall,
- attractive digital resource does not align to target,
- assessment measures vocabulary while lesson target requires reasoning,
- teacher plans one activity but no method for checking the intended effect.

## Module 02 — Standards-Based Instruction

Purpose: learn the ten current instructional competencies as a connected system rather than ten isolated definitions.

### Cluster A — Build knowledge

- Identifying Critical Content
- Previewing New Content
- Processing New Content
- Using Questions to Help Students Elaborate on Content

Core comparisons:

- previewing vs reviewing,
- processing vs elaborating,
- critical content vs simply stating an objective,
- questioning vs question quantity.

### Cluster B — Deepen knowledge

- Reviewing Content
- Helping Students Practice Skills, Strategies, and Processes
- Helping Students Examine Similarities and Differences

Core comparisons:

- review vs preview,
- practice vs repetition without feedback,
- compare/contrast vs simply listing characteristics.

### Cluster C — Analyze and revise

- Helping Students Examine Their Reasoning
- Helping Students Revise Their Knowledge

Core comparisons:

- checking an answer vs examining reasoning,
- correcting an error vs revising a mental model,
- debugging code vs examining reasoning about why the code behaves as it does.

### Cluster D — Use knowledge

- Helping Students Engage in Cognitively Complex Tasks

Core questions:

- What makes a task cognitively complex?
- How does complexity differ from difficulty or workload?
- What evidence shows that students are using knowledge rather than following a procedure?

## Module 03 — Conditions for Learning

Purpose: understand the conditions that allow rigorous instruction to work.

### Progress and feedback

- Using Formative Assessment to Track Progress
- Providing Feedback and Celebrating Progress

Key distinction:

> collecting evidence is not the same as giving feedback about that evidence.

### Rigorous learning

- Organizing Students to Interact with Content
- Using Engagement Strategies

Key distinction:

> students sitting together is not automatically meaningful interaction with content, and visible energy is not automatically evidence of learning.

### Classroom environment

- Establishing and Acknowledging Adherence to Rules and Procedures
- Establishing and Maintaining Effective Relationships in Student-Centered Classrooms
- Communicating High Expectations for Each Student to Close the Achievement Gap

Key course problem:

Avoid reducing this domain to behavior management. Tie classroom conditions back to access to rigorous learning.

## Module 04 — Professional Responsibilities

Purpose: connect instructional expertise to professional conduct, continued learning, leadership, and collaboration.

Competencies:

- Adhering to School and District Policies and Procedures
- Maintaining Expertise in Content and Pedagogy
- Promoting Teacher Leadership and Collaboration

Useful scenarios:

- new instructional technology conflicts with district procedure,
- a teacher notices a recurring instructional weakness and chooses a professional-learning response,
- collaboration produces meetings but no instructional change,
- teacher leadership means improving shared practice rather than holding a title.

## Module 05 — Framework History

Purpose: understand how the current model relates to the earlier 2011 Learning Map without treating the older map as the current standard.

Topics:

- four legacy domains,
- Design Questions,
- 60-element architecture,
- movement to the focused 23-competency model,
- conceptual continuity,
- organizational changes,
- stronger desired-effect/evidence framing.

Do not reproduce the full proprietary map.

## Module 06 — Observation Lab

Purpose: analyze teaching without being told which competency is being tested.

Scenario types:

- clean single-competency case,
- overlapping competencies,
- surface-positive but evidence-poor classroom,
- mixed student evidence,
- teacher adaptation during the lesson,
- observer overclaim,
- teacher overclaim,
- insufficient evidence.

Learner response structure:

```text
Instructional target
Relevant practice(s)
Desired effect
Observed evidence
Evidence limitations
Diagnosis
Adaptation / next move
Additional evidence needed
```

## Module 07 — Defense Lab

Purpose: prepare for real instructional questioning.

### Principal mode

Questions about:

- alignment,
- purpose,
- evidence,
- what changed during the lesson,
- next steps.

### Instructional coach mode

Questions about:

- why the practice worked or failed,
- misconception patterns,
- alternate adaptations,
- evidence quality.

### Skeptic mode

Questions challenge superficial framework language:

- Isn't this just group work?
- Isn't this just questioning?
- Why does this need a framework label?
- How do you know the activity produced learning?

### Framework expert mode

Questions focus on precise distinctions among neighboring competencies.

### Rapid response mode

Short prompts:

```text
Purpose?
Desired effect?
Evidence?
Non-example?
Adaptation?
Neighboring competency?
Why not that one?
```

## Module 08 — Integrated Lesson Analysis

Purpose: connect planning, instruction, conditions for learning, and professional reflection.

The learner receives a full lesson or case and answers:

1. What is the learning target?
2. Is the task aligned to the target?
3. Which instructional practices are evident?
4. What desired effects should occur?
5. What evidence is available?
6. What evidence is missing?
7. Where does instruction need adaptation?
8. Which classroom conditions support or interfere with learning?
9. How would you explain the decisions afterward?
10. What would you change next time?

## Standard page anatomy

Every published competency page should follow the same **reasoning architecture**, but not become mechanically templated.

Required content:

```text
Concept
Why it exists
Instructional mechanism
Desired effect
What it looks like
What it does NOT prove
Evidence
Common confusion
CS classroom example
Failure mode
Adaptation
Compare / contrast
Recall
Scenario
Defense
Sources
```

The writing should vary according to the concept. Do not generate identical paragraphs with terminology swapped out.

## Course media plan

### Mermaid

Default for:

- causal loops,
- concept relationships,
- decision trees,
- framework architecture,
- comparison diagrams.

### SVG / CSS

Use for:

- annotated examples,
- evidence hierarchies,
- concept cards,
- visual contrasts.

### Three.js

Use selectively for:

- evidence relationship visualizations,
- interactive classroom evidence inspection,
- animated concept comparison,
- scenario environments where spatial inspection is actually part of the reasoning task.

Do not use Three.js for ordinary reading pages.

## No-account design

The course must remain useful without saved progress.

Instead of software progress tracking, each page provides:

- retrieval questions,
- self-check criteria,
- repeatable exercises,
- links to related concepts,
- increasingly difficult scenarios.

The learner decides when to revisit content.

## Definition of course readiness

The full course is not ready merely when all 23 competency pages exist.

It is ready when:

- every current label is source verified,
- each page has original substantive instruction,
- neighboring concepts have explicit distinctions,
- scenarios cover multiple classroom contexts,
- evidence and adaptation are central throughout,
- no copyrighted official protocol has been cloned,
- Foundations supports the later modules,
- the Observation Lab mixes domains rather than telegraphing answers,
- the Defense Lab can expose shallow memorization,
- source provenance is visible and maintained.
