# Framework Analysis Skill

## Purpose

Use this skill to analyze a teaching/evaluation framework without turning the repository into a copied rubric.

## Analysis unit

For each competency/practice, build an original analysis around:

1. **Identity** — canonical name, domain, source version.
2. **Instructional problem** — what problem the practice addresses.
3. **Mechanism** — how the practice is expected to influence learning.
4. **Observable teacher action** — what implementation may look like.
5. **Observable student evidence** — what would indicate impact.
6. **False positives** — activity that resembles the practice but misses the purpose.
7. **Adaptation triggers** — evidence suggesting instruction should change.
8. **Possible adaptations** — original, context-appropriate options.
9. **Transfer** — examples across subjects/settings.
10. **Reflection prompts** — questions that improve teacher reasoning.

## Version discipline

- Record the framework version/source on every canonical framework page.
- Never merge legacy and current elements because they sound similar.
- Crosswalks are analytical artifacts and must be labeled as such unless an official crosswalk is cited.

## Expertise target

Do not optimize for memorization. Optimize for the teacher's ability to:

`recognize → plan → implement → monitor → diagnose → adapt → explain → transfer`

## Scoring boundary

Do not invent official evaluation scores. Practice-level self-assessment may be designed later, but it must be clearly distinct from an employer/district evaluation and should prioritize evidence quality and reflective reasoning over pseudo-precision.
